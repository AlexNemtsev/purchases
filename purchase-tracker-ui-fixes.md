# «Учёт закупок» — правки интерфейса после T4

Документ описывает запланированные правки. Код не менялся: реализация —
после согласования. Источники истины остаются прежними: ТЗ v3 и
`purchase-tracker-tasks-fsd.md`.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Возврат из «Категорий» в закупку | Кнопка «Назад» в шапке, если пришли из закупки |
| Итог категории в закупке | Как сейчас: «Расходы» и «Итого», без списка операций |
| Меню действий | Кнопка «⋯» и shadcn `DropdownMenu` (удобнее для телефона, чем долгое нажатие) |
| Операции чека | Отдельный маршрут `/purchases/[purchaseId]/receipts/[receiptId]`, переход по тапу на карточку чека |

Пункт 6 просил «контекстное меню». По выбору используется `DropdownMenu`
из shadcn-svelte; `ContextMenu` (правый клик/долгое нажатие) в проект уже
добавлен, но не применяется: на телефоне он неочевиден.

## 1. Ввод суммы скидки подставляет `,00`

**Причина.** В `shared/ui/AmountOrPercentInput.svelte` `$effect` копирует
`value` в `text` при каждом изменении. Ввод «5» вызывает `onChange(…, 500)`,
значение меняется, эффект записывает `text = '5,00'` и мешает дальнейшему
вводу.

**Правка.**
- Отдельная переменная `text` синхронизируется с `value` только при
  внешнем изменении: смене `mode`, открытии формы, сбросе. Пока поле в
  фокусе и текст разбирается в то же число, текст не перезаписывается.
- Допустимо форматировать значение при потере фокуса (`onblur`), но не
  во время ввода.
- Переключение «Сумма ↔ Процент» по-прежнему подставляет эквивалент.
- Тот же принцип проверить в `MoneyInput`/`PermilleInput` и в формах
  чека и операции (сумма, возврат).

**Проверка.** Unit-тест на логику синхронизации (вынести в чистую
функцию в `shared/lib`), ручной ввод `10`, `10,5`, `1 234,56`, `0,5` в
модалках чека и операции; тест-кейсы 25–27 не ломаются.

## 2. Нельзя вернуться из «Категорий» в закупку

**Причина.** Ссылка «Управление категориями» в `PurchaseHeader` ведёт на
`/categories`; нижняя вкладка «Закупки» ведёт на `/`, а не в закупку.

**Правка.**
- Ссылка из закупки: `/categories?from=<purchaseId>`; на экране
  категорий при наличии корректного `from` в шапке показывается кнопка
  «← Назад». Она ведёт на `/purchases/<purchaseId>` через `resolve`, а не
  через `history.back()`: результат тот же, но работает и после
  перезагрузки или открытия по прямой ссылке. Если нужен именно
  `history.back()`, скажите — заменю.
- `from` проверяется: если закупки нет, кнопка не показывается.
- `PageHeader` получает необязательный слот/проп для кнопки назад
  (общий для экрана чека, п. 3).

**Проверка.** Закупка → категории → «Назад» → та же закупка; прямой
переход на `/categories` без кнопки; перезагрузка на `/categories?from=…`.

## 3. Операции чека — на отдельном экране

**Было.** `PurchaseByReceipts` рисует операции под каждым чеком.

**Станет.**
- Новый маршрут `src/routes/purchases/[purchaseId]/receipts/[receiptId]/+page.svelte`
  (тонкий, собирает виджет и фичи).
- Новый виджет `widgets/receipt-operations` (список операций чека,
  «Добавить операцию», пустое состояние) с `ui/`-сегментом и
  `index.ts`.
- Экран закупки (вид «Чеки») показывает только карточки чеков
  (`ReceiptCard`, сумма, скидка, итог, число операций); тап по карточке
  открывает экран чека. «Добавить чек» остаётся.
- Экран чека: шапка со сводкой чека (сумма, скидка, итог, расхождение),
  кнопка «← К закупке», меню чека «⋯» (изменить/удалить), список операций
  с меню «⋯» (изменить/удалить), кнопка «Добавить операцию».
- Удаление чека на экране чека возвращает в закупку; несуществующий
  чек или чек другой закупки — состояние «Чек не найден» со ссылкой
  назад.
- Все диалоги (`OperationEditor`, `ReceiptEditor`, `ConfirmDialog`)
  переиспользуются; логика сторов не меняется.
- Нижнее меню: вкладка «Закупки» активна и на вложенных маршрутах (уже
  работает по префиксу `/purchases/`).
- Пустые папки `src/routes/purchases/[slug]` и `src/routes/purchases/ui`
  удалить, если не используются.

**ТЗ.** §10 описывает чек с операциями внутри экрана закупки. Это
изменение раскладки, а не правил расчёта; в ТЗ/задачах отметить
отдельной строкой («операции чека — отдельный экран»). Тест-кейс 34
(одинаковые операции в обоих видах закупки) пересматривается, см. п. 5.

## 4. Компоненты shadcn-svelte для инпутов и карточек

Уже установлены: `button`, `card`, `input`, `label`, `field`,
`textarea`, `dialog`, `drawer`, `alert-dialog`, `dropdown-menu`,
`context-menu`, `navigation-menu`, `separator`, `scroll-area`.

Добавить через `shadcn-svelte add`: `select` (режим «Сумма/Процент»,
категория операции, база процента), `checkbox` (переключатель «Показывать
архивные»), `badge` (замена `CategoryBadge`-разметки), `alert`
(предупреждения и ошибки, `WarningList`), `toggle-group` или `tabs`
(переключатель «Чеки/Категории»).

Замены:

| Сейчас | Станет |
|---|---|
| `<input>` в `MoneyInput`, `PermilleInput`, текстовые поля форм | `Input` + `Field`/`Label`, ошибка через `Field.Error` |
| `<select>` в `AmountOrPercentInput`, `OperationEditor`, `ReceiptEditor` | `Select` |
| `<textarea>` комментариев | `Textarea` |
| `<input type="checkbox">` на экране категорий | `Checkbox` + `Label` |
| Самописные `<article class="rounded-lg border …">` в `PurchaseCard`, `ReceiptCard`, `OperationCard`, `CategoryList`, `PurchaseHeader`, виджетах | `Card.Root/Header/Title/Description/Content` |
| Самописная метка категории | `Badge` |
| Кнопки «Чеки/Категории» | `ToggleGroup` (или `Tabs`) |
| `WarningList`, `actionError` | `Alert` |
| `EmptyState` | оставить; внутри `Card`, если подходит по виду |

Правила: код компонентов в `src/lib/components/ui` руками не править;
обёртки (`MoneyInput`, `PermilleInput`, `AmountOrPercentInput`) остаются
в `shared/ui` и строятся поверх shadcn. FSD-границы сохраняются:
сущности импортируют shadcn через `$lib`, как уже делают виджеты.

## 5. Категории в закупке: без операций

- `PurchaseByCategories`: на категорию — одна `Card`/строка с `Badge`
  категории, «Расходы» и «Итого» (как сейчас), без `OperationCard` и
  кнопок изменения/удаления операций; убираются `onEditOperation`,
  `onDeleteOperation` и зависимость от `OperationCard`.
- Категории без операций в закупке не показываются; пустое состояние
  остаётся.
- Правка и удаление операций доступны только на экране чека (п. 3).
- Общий итог закупки не меняется.

**ТЗ.** Меняется смысл тест-кейса 34: «одни и те же операции видны в
обоих представлениях» → «итоги по категориям в закупке совпадают с
суммой операций, видимых на экранах чеков; правка операции на экране
чека сразу меняет итог категории». Отметить в ТЗ/задачах как
осознанное изменение и перенести проверку в unit/интеграционный тест
`calculateCategorySummary` и ручной сценарий.

## 6. Меню действий вместо кнопок «Изменить/Удалить/В архив»

Единый компонент в `shared/ui`: `ActionsMenu` на базе shadcn
`DropdownMenu` с триггером-иконкой «⋯» (`Button variant="ghost"
size="icon"`, `aria-label="Действия"`), принимающий список пунктов
(`label`, `onSelect`, `destructive`). Размер триггера не меньше 40×40 px.

Где применить:

| Экран | Пункты |
|---|---|
| Список закупок (`PurchaseList`) | Изменить, Удалить |
| Шапка закупки (`PurchaseHeader`) | Изменить, Удалить |
| Список чеков в закупке | Изменить, Удалить |
| Экран чека (шапка) | Изменить чек, Удалить чек |
| Операции на экране чека | Изменить, Удалить |
| Категории (`CategoryList`) | Изменить, В архив / Вернуть |

Удаление по-прежнему через `ConfirmDialog` с числом каскадно
удаляемых сущностей; архивирование без подтверждения (ТЗ §18).
Тап по карточке (закупка, чек) открывает экран; нажатие на «⋯» не
должно запускать переход (`stopPropagation` / вне ссылки).

## Порядок работ

1. Исправить п. 1 + тест; ручная проверка форм.
2. Добавить компоненты shadcn (п. 4), перевести `shared/ui` инпуты.
3. `ActionsMenu` (п. 6) и перенос кнопок.
4. Экран чека и виджет операций (п. 3); упрощение карточек чека в
   закупке.
5. Упрощение вида «Категории» (п. 5).
6. Кнопка «Назад» (п. 2).
7. Карточки на `Card` (п. 4), `Alert`, `Badge`.
8. Обновить ТЗ (§10, тест-кейс 34) и `purchase-tracker-tasks-fsd.md`.

## Проверка

- `pnpm test`, `pnpm check`, `pnpm check:fsd`, ESLint (включая
  `import-x/no-cycle`), `pnpm build` и `BASE_PATH=/demo pnpm build`.
- Ручной сценарий на мобильном viewport: категория → закупка → чек
  (две скидки) → экран чека → операции (скидка, возврат) → вид
  «Категории» → «Управление категориями» → «Назад» → экспорт JSON →
  перезагрузка → каскадное удаление.

  `200.html` уже обслуживает вложенные маршруты).

## Риски

- Рост объёма: затронуты почти все UI-компоненты; делить на отдельные
  коммиты по порядку выше.
- Сторонние shadcn-компоненты добавляют вес в precache (небольшой);
  проверить размер после сборки.
- Изменение §10 и тест-кейса 34 в ТЗ — нужно подтверждение.
