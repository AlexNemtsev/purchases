# «Учёт закупок»

Мобильное PWA для ведения закупок, чеков и расходов по категориям. Данные
хранятся локально в браузере — аккаунт и подключение к серверу не нужны.

## Возможности

- Создание закупок и чеков, добавление операций с категориями.
- Расчёт скидок для чеков и отдельных операций, учёт возвратов и сводных итогов.
- Сводка закупки по чекам или категориям.
- Управление категориями, включая архивирование и восстановление.
- Выгрузка данных в JSON, калькулятор кешбэка и переключение темы.
- Установка как PWA и доступ к ранее загруженному приложению без сети.

Данные находятся в хранилище браузера и не синхронизируются между устройствами.
Регулярно сохраняйте резервную копию через **Разное → Выгрузить JSON**.

## Запуск

Требуются Node.js и pnpm.

```sh
pnpm install
pnpm dev
```

Vite запустит приложение в режиме разработки. Для проверки и сборки используйте:

```sh
pnpm check       # Проверка Svelte и TypeScript
pnpm test        # Тесты Vitest
pnpm check:fsd   # Проверка границ Feature-Sliced Design
pnpm lint        # ESLint с автоматическим исправлением
pnpm build       # Статическая production-сборка
pnpm preview     # Локальный просмотр production-сборки
```

Тесты находятся рядом с кодом (`*.test.ts` в `src/`) и запускаются в среде
Node.js. Конфигурация Vitest включает файлы `src/**/*.test.ts`.

## Разработка

Приложение построено на SvelteKit в SPA-режиме: серверный рендеринг отключён,
а для статической сборки используется адаптер `adapter-static`. Основные
технологии: Svelte 5, TypeScript, Vite, Tailwind CSS и shadcn-svelte.

Код организован по Feature-Sliced Design:

```text
src/
├── app/       # Инициализация приложения и контекст
├── routes/    # Страницы и маршрутизация SvelteKit
├── widgets/   # Крупные составные блоки интерфейса
├── features/  # Пользовательские действия
├── entities/  # Закупки, чеки, операции и категории
├── shared/    # Общие API, утилиты, конфигурация и UI
└── lib/       # UI-компоненты и вспомогательные функции
```

Основные страницы: `/` — список закупок, `/purchases/<id>` — закупка,
`/purchases/<id>/receipts/<id>` — чек, `/categories` — категории,
`/misc` — дополнительные инструменты и экспорт.

## Сборка и размещение

Production-сборка создаётся командой `pnpm build` в каталоге `build/`.
Проект настроен для статического размещения; для Vercel используется
`vercel.json`.

При размещении в подпапке задайте `BASE_PATH` при сборке. Значение должно
начинаться с `/` и не должно заканчиваться `/`:

```sh
BASE_PATH=/purchases pnpm build
```

Для размещения в корне сайта переменную `BASE_PATH` задавать не нужно.
