# PWA «Учёт закупок» — техническое описание v1

## 1. Назначение

Мобильное offline-first PWA для учёта фактической стоимости закупок с учётом:

- нескольких чеков/заказов в рамках одной закупки;
- скидок, кэшбэков и других уменьшений стоимости;
- группировки приобретённых товаров;
- расходов и возвратов;
- итоговой стоимости закупки после применения скидки.

Приложение не имеет backend и аккаунтов. Все данные хранятся локально в IndexedDB.

### Технологический стек

- Svelte 5
- Vite
- Shadcn-svelte
- TypeScript
- IndexedDB
- PWA / Service Worker
- мобильная ориентация интерфейса

---

## 2. Доменная модель

Основная структура:

```text
Purchase
│
├── Receipt[]
│
└── Group[]
      │
      └── GroupItem[]
```

Связей между `Receipt` и `Group` нет.

Это принципиально:

- `Receipt` определяет скидку закупки.
- `Group` описывает, на что потрачены деньги.

---

## 3. Терминология

В пользовательском интерфейсе:

- **Закупка** — одна логическая операция приобретения.
- **Чек** — отдельный заказ/чек внутри закупки.
- **Группа** — логическая группировка расходов.
- **Позиция** — расход или возврат внутри группы.

Например:

```text
Закупка «Ozon — сентябрь»

Чеки:
  Заказ №123
  Заказ №124

Группы:
  Продукты
  Бытовая химия
  Для дома
```

В коде сущности называются:

```text
Purchase
Receipt
Group
GroupItem
```

---

## 4. Денежные значения

Денежные значения не хранить как `number` с десятичной частью.

Использовать целое количество копеек:

```ts
amountKopecks: number
```

Примеры:

```text
1299.99 ₽ → 129999
500 ₽     → 50000
-10.50 ₽  → -1050
```

Это позволяет избежать ошибок JavaScript floating point.

Проценты хранятся как `number`:

```text
20
16.5
125.7
```

Точность процентов — 0.1%.

# 5. Сущность Purchase

```ts
interface Purchase {
    id: string
    title: string
    date: string
    createdAt: string
    updatedAt: string
}
```

Суммы и скидки не хранятся в `Purchase`, поскольку являются derived data и вычисляются из чеков.

Не хранить:

```text
total
discount
discountPercent
netTotal
```

# 6. Сущность Receipt

```ts
interface Receipt {
    id: string
    purchaseId: string

    amountKopecks: number

    discountMode: 'amount' | 'percent'

    discountAmountKopecks: number
    discountPercent: number

    comment: string

    createdAt: string
    updatedAt: string
}
```

## 6.1. Режим скидки

Пользователь выбирает способ ввода скидки:

```text
◉ ₽
○ %
```

или:

```text
○ ₽
◉ %
```

### Режим `amount`

Пользователь вводит:

```text
Сумма: 5 000 ₽
Скидка: 1 000 ₽
```

Процент рассчитывается:

```text
1000 / 5000 × 100 = 20%
```

### Режим `percent`

Пользователь вводит:

```text
Сумма: 5 000 ₽
Скидка: 20%
```

Сумма скидки:

```text
5000 × 20% = 1000 ₽
```

### Изменение суммы

Выбранный режим скидки сохраняется.

Если было:

```text
Сумма: 5 000 ₽
Скидка: 20%
Сумма скидки: 1 000 ₽
```

и сумма изменена на 6 000 ₽:

```text
Сумма: 6 000 ₽
Скидка: 20%
Сумма скидки: 1 200 ₽
```

Аналогично в режиме ввода скидки в рублях:

```text
Сумма: 5 000 ₽
Скидка: 1 000 ₽
Скидка: 20%
```

Если сумма меняется, процент пересчитывается.

---

## 6.2. Скидка может быть больше 100%

Ограничений на величину скидки относительно суммы нет.

Например:

```text
Сумма: 500 ₽
Скидка: 600 ₽
Скидка: 120%
```

Стоимость после скидки:

```text
500 - 600 = -100 ₽
```

Отрицательная стоимость является валидным состоянием.

Не устанавливать ограничение вида:

```text
discount <= amount
```

# 7. Расчёты Purchase

Для всех чеков:

```ts
receiptTotal =
    sum(receipt.amountKopecks)
```

Общая скидка:

```ts
discountTotal =
    sum(receipt.discountAmountKopecks)
```

Стоимость после скидки:

```ts
netTotal =
    receiptTotal - discountTotal
```

Процент скидки закупки:

```ts
discountPercent =
    receiptTotal === 0
        ? null
        : discountTotal / receiptTotal * 100
```

Если сумма чеков равна нулю, процент скидки математически не определён и в UI отображается `—`.

# 10. Расчёт группы

Сумма расходов:

```ts
expenses =
    sum(items[type === 'expense'].amountKopecks)
```

Сумма возвратов:

```ts
refunds =
    sum(items[type === 'refund'].amountKopecks)
```

Сумма группы до скидки:

```ts
grossAmount =
    expenses - refunds
```

Например:

```text
Расходы:
1000
2000
500

Возвраты:
300

Итого:
3200 ₽
```

---

# 11. Скидка группы

Группа использует процент скидки всей закупки.

```ts
groupDiscount =
    round(grossAmount * purchaseDiscountPercent / 100)
```

Стоимость группы после скидки:

```ts
groupNetAmount =
    grossAmount - groupDiscount
```

Пример:

```text
Группа                  5 000 ₽
Скидка закупки             20%
Скидка                    1 000 ₽
Итого                     4 000 ₽
```

Скидка может быть больше 100%, поэтому итог группы также может быть отрицательным.

---

# 12. Суммы закупки

У закупки есть две основные суммы.

### Сумма без скидки

Это сумма всех чеков:

```text
gross =
    Σ receipt.amount
```

### Сумма с учётом скидки

```text
net =
    gross - discount
```

Группы не участвуют в расчёте общей стоимости закупки.

Группы являются независимой детализацией расходов.

---

# 13. Сверка чеков и групп

Дополнительно вычисляется сумма групп до скидки:

```text
groupsGrossTotal =
    Σ group.grossAmount
```

Сравниваются:

```text
receiptGrossTotal
groupsGrossTotal
```

Разница:

```ts
difference =
    receiptGrossTotal - groupsGrossTotal
```

Если значения различаются, показывается предупреждение.

Например:

```text
┌────────────────────────────────┐
│ ⚠ Суммы отличаются             │
│                                │
│ По чекам       8 000 ₽         │
│ По группам     7 800 ₽         │
│ Разница          200 ₽         │
└────────────────────────────────┘
```

Несовпадение не является ошибкой и не блокирует сохранение.

# 15. Создание закупки

При нажатии `+`:

1. Создаётся `Purchase`.
2. `date` устанавливается в текущую дату.
3. Название автоматически генерируется.
4. Открывается экран закупки.

Пример названия:

```text

```

Пользователь может изменить его.

Первая группа автоматически не создаётся.

Причина: чеки являются более приоритетной сущностью и пользователь должен иметь возможность сначала внести чеки.

# 25. Удаление

Поддерживается удаление всех сущностей:

- Purchase
- Receipt
- Group
- GroupItem

## Удаление Purchase

Каскадное удаление:

```text
Purchase
├── Receipts → delete
├── Groups   → delete
│   └── GroupItems → delete
└── Purchase → delete
```

После удаления дочерних сущностей не остаётся ссылок на удалённую закупку.

## Удаление Receipt

Удаляется только чек.

## Удаление Group

Удаляется группа и все её позиции.

## Удаление GroupItem

Удаляется только позиция.

Для разрушительных действий показывается confirmation dialog.

Swipe-to-delete может быть добавлен как дополнительный мобильный UX, но не является обязательной частью первой версии.

# 28. Почему сущности хранятся в отдельных stores

Не рекомендуется хранить всю закупку одним вложенным объектом:

```ts
interface Purchase {
    id: string
    receipts: Receipt[]
    groups: Group[]
}
```

в качестве единственной записи IndexedDB.

Отдельные stores дают:

- более простой CRUD;
- независимое изменение чеков и групп;
- более простое каскадное удаление;
- индексы по родительским сущностям;
- меньше объём изменяемых данных;
- более удобные миграции схемы.

Storage model отделён от модели, используемой UI.

Например:

```ts
interface ReceiptSummary {

    discountAmountKopecks: number
    discountPercent: number | null

```

```ts
interface PurchaseSummary {
    grossAmountKopecks: number
    discountAmountKopecks: number
    discountPercent: number | null
    netAmountKopecks: number

    groupsGrossAmountKopecks: number
    groupsDifferenceKopecks: number
}
```

```ts
interface GroupSummary {
    expensesKopecks: number
    refundsKopecks: number
    grossAmountKopecks: number

    discountAmountKopecks: number
    netAmountKopecks: number
}
```

# 30. Слой расчётов

Расчёты не должны находиться непосредственно в Svelte-компонентах.

Рекомендуемые чистые функции:

```ts
calculateReceipt()
calculatePurchase()
calculateGroup()
calculateGroupDiscount()
```

Например:

```ts
function calculateReceipt(
    amountKopecks: number,
    discountMode: DiscountMode,
    discountValue: number
): ReceiptSummary
```

и:

```ts
function calculatePurchaseSummary(
    receipts: Receipt[],
    groups: GroupWithItems[]
): PurchaseSummary
```

Это позволяет тестировать бизнес-логику независимо от Svelte и IndexedDB.

# 33. Ключевые бизнес-правила

1. Закупка может не иметь чеков.
2. Закупка может не иметь групп.
3. Группа может не иметь позиций.
4. Чеки и группы не связаны напрямую.
5. Чеки являются источником информации о скидке закупки.
6. Сумма закупки до скидки = сумма чеков.
7. Сумма закупки после скидки = сумма чеков − сумма скидок чеков.
8. Скидка закупки распределяется на группы в виде процентной ставки.
9. Сумма группы = расходы − возвраты.
10. Сумма группы после скидки = сумма группы − скидка группы.
11. Суммы чеков и групп могут различаться.
12. Несовпадение сумм не блокирует сохранение.
13. Скидка может быть больше 100%.
14. Итоговая стоимость может быть отрицательной.
15. Денежные значения хранятся в копейках.
16. Проценты имеют точность 0.1%.
17. Удаление закупки каскадно удаляет все дочерние сущности.
18. Все данные хранятся локально в IndexedDB.
19. Первая группа автоматически не создаётся.
20. При создании закупки дата устанавливается текущей датой.

---

# 34. Что не входит в первую версию

Не требуется реализовывать:

- backend;
- синхронизацию;
- аккаунты;
- авторизацию;
- фотографии чеков;
- OCR;
- импорт/экспорт;
- поиск;
- фильтрацию;
- аналитику;
- графики;
- привязку групп к конкретным чекам;
- сложные жесты;
- drag & drop.

Архитектура должна при этом позволять добавить эти возможности позже.

# 35. Архитектурный принцип

Основное разделение ответственности:

```text
Receipt
    ↓
определяет финансовую скидку закупки

Purchase
    ↓
определяет итоговую стоимость

Group
    ↓
определяет распределение стоимости

GroupItem
    ↓
определяет состав группы
```

Главный принцип модели:

> **Чеки отвечают за финансовые исходные данные, группы — за классификацию расходов.**

Это позволяет иметь неполную классификацию расходов, не влияя на фактическую стоимость закупки.
